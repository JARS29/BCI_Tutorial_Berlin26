# BCI Tutorial — Motor Imagery, from Theory to Online Decoding

A self-contained, ~90-minute hands-on tutorial on Brain-Computer Interfaces
(BCI), built around a Motor Imagery (MI) pipeline: signal cleaning, feature
extraction, classification, evaluation, and a simulated real-time online decoding stage.

The dataset is the [PhysioNet EEG Motor Movement/Imagery
dataset](https://physionet.org/content/eegmmidb/1.0.0/), fetched
automatically through `mne.datasets.eegbci` — no manual download needed.

---

## Contents

| File | What it is |
|---|---|
| **`BCI_Tutorial_Slides.pdf`** | The theory + walkthrough deck: BCI fundamentals, signal processing/cleaning, feature extraction, machine learning & classifiers, neurofeedback, applications — plus the tutorial-style slides on experiment design, LSL synchronization, and online decoding that mirror the two notebooks below. |
| **`BCI_Tutorial_HandsOn.ipynb`** | The main analysis notebook. Loads 3 real Motor Imagery runs (PhysioNet, subject 1, runs 4/8/12), cleans the signal (1 Hz high-pass + ICA, with the fitted ICA saved to disk), band-pass filters to the mu/beta range (7–30 Hz), epochs the data, benchmark feature extraction and classifiers, trains the best pipeline on 2 of the 3 runs, and evaluates on the fully held-out 3rd run two ways: (a) trial-by-trial, and (b) a continuous, sample-by-sample "replay" that simulates what an online decoder would see live. |
| **`BCI_Tutorial_ExperimentDesign.ipynb`** | A companion, cell-by-cell walkthrough of `experiment_stimulus.py`'s logic — the trial-timing plan, a balanced/shuffled condition list, an LSL marker outlet, and the trial loop — with a runnable demo (real PsychoPy window on a machine with a screen; a fast mocked run otherwise, so the logic is visible even headless/in Colab). |
| **`experiment_stimulus.py`** | The real, runnable PsychoPy script for an actual MI recording session: presents the fixation/cue/imagery/rest trial sequence and pushes an LSL marker at every event. |
| **`lsl_online_decoder.py`** | The real-time decoding loop: pulls chunks from a live LSL EEG stream, applies the *same pretrained* ICA and a causal band-pass, predicts with the CSP+LDA pipeline trained in the hands-on notebook, and pushes each prediction to a new LSL stream. |
| **`send_eeg_data.py`** | A minimal synthetic LSL EEG outlet (32 channels, sine + noise), for exercising `lsl_online_decoder.py` end-to-end without a real amplifier. |
| **`requirements.txt`** | Python dependencies, grouped by which file needs them. |
| **`.gitignore`** | Excludes virtual environments, the downloaded PhysioNet cache, and the model/ICA files the notebook generates. |

**What the hands-on notebook produces**, used by the live decoder:
`ica_weights-ica.fif` (the fitted ICA) and `csp_lda_pipeline.joblib` (the
trained CSP+LDA model). These are regenerated by running the notebook, so
they aren't committed to the repo (see `.gitignore`).

## Running it

Two notebooks are involved. `BCI_Tutorial_HandsOn.ipynb` is pure Python —
runs anywhere. `BCI_Tutorial_ExperimentDesign.ipynb`'s early cells are pure
Python too, but its real stimulus window (Section 5) needs `psychopy` **and**
a real display; without either, it automatically falls back to a mock run
(see the notebook itself) — so it still runs everywhere, just without opening
an actual window.

### Option A — Local machine, `uv` + VS Code (recommended)

This is the only option that can open a **real** PsychoPy window and talk to
a **real** LSL stream, so use it for the parts of the tutorial you'll demo
live.

**1. Install `uv`** (one-time)

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

**2. Clone the repo and create the environment**

```bash
git clone <this-repo-url>
cd <repo-folder>
uv venv --python 3.11
```

**3. Install the dependencies**

```bash
uv pip install -r requirements.txt
```

> `psychopy` is a heavy dependency (audio/video backends, wxPython). If the
> install complains, installing it on its own first (`uv pip install
> psychopy`) usually surfaces the real error more clearly than installing it
> together with everything else.

**4. Register the kernel and open in VS Code**

```bash
uv run python -m ipykernel install --user --name bci-tutorial \
    --display-name "BCI tutorial (uv)"
```

Then in VS Code: open the repo folder → open either notebook → click the
kernel picker (top right) → **Select Another Kernel** → **Jupyter
Kernel...** → **BCI tutorial (uv)**. (Needs the *Python* and *Jupyter*
extensions installed once, from the Extensions panel.)

**5. Run**

- `BCI_Tutorial_HandsOn.ipynb`: run top to bottom. The first run downloads
  the PhysioNet EEGBCI runs (subject 1, runs 4/8/12) — needs internet once;
  MNE caches them locally afterward. It ends by saving `ica_weights-ica.fif`
  and `csp_lda_pipeline.joblib`.
- `BCI_Tutorial_ExperimentDesign.ipynb`: run top to bottom. Section 5 opens
  a real PsychoPy window and plays a real (sped-up, 4-trial) demo block.
- For a genuinely live demo: `python experiment_stimulus.py --n-trials 40`
  in one terminal, an EEG LSL stream in another (`python send_eeg_data.py`
  to simulate one, or a real amplifier), and
  `python lsl_online_decoder.py` in a third to see live predictions.

### Option B — Google Colab (nothing to install, works from any browser)

Good for `BCI_Tutorial_HandsOn.ipynb` end-to-end (including the real
PhysioNet download — Colab has internet access). Good for reading/running
`BCI_Tutorial_ExperimentDesign.ipynb` too, but only in its **mock** mode —
Colab has no display, no audio, and no LSL network reachable from its VM, so
a real PsychoPy window / real LSL stream can never open there. That's fine:
the notebook detects this and falls back automatically, so the full trial
logic and marker sequence are still visible.

**Steps**

1. Go to [colab.research.google.com](https://colab.research.google.com) →
   **File → Open notebook → GitHub**, paste this repo's URL, and pick a
   notebook (or **Upload** the `.ipynb` directly).
2. As the very first cell, install what Colab doesn't ship with:

   ```python
   !pip install -q mne pyriemann PyWavelets
   ```

   (`numpy`, `pandas`, `matplotlib`, `scipy`, `scikit-learn`, `joblib` are
   already preinstalled on Colab.)
3. Run the rest of the notebook normally — no GPU needed.
4. For `BCI_Tutorial_ExperimentDesign.ipynb`, **don't** try to `pip install
   psychopy`/`pylsl` on Colab — it's slow, often fails to build there, and
   wouldn't help anyway (no display). Just run the cells as they are;
   Sections 3 and 5 will each print a short note and continue in mock mode.

### Option C — Other free "run it online" options

- **Binder** ([mybinder.org](https://mybinder.org)) — point it at this
  GitHub repo (it already has a `requirements.txt`) and it builds a
  temporary, shareable Jupyter environment with one click — handy for
  workshop participants who don't want to install anything and don't have a
  Google account. Downsides: first launch is slow (building the image), and
  the session is ephemeral (nothing is saved unless downloaded). Skip
  `psychopy`/`pylsl` from the environment it builds if you only need the
  hands-on notebook — it keeps the build faster.
- **Kaggle Notebooks** — similar profile to Colab (free CPU, browser-based,
  `!pip install` works, has internet access), useful as a fallback for
  someone without a Google account but with a Kaggle one.

Either of these only substitutes for Option B, not Option A — the live
PsychoPy/LSL demo still needs a real machine with a screen.
